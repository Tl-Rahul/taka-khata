# টাকার খাতা · Taka Khata

ব্যক্তিগত অর্থ ব্যবস্থাপনার পূর্ণাঙ্গ ওয়েব অ্যাপ — অ্যাকাউন্ট/ওয়ালেট, আয়-ব্যয়, ট্রান্সফার, দেনা ও পাওনা (আসল/সুদ আলাদা), বাজেট, সঞ্চয় লক্ষ্য, বিল ও নিয়মিত লেনদেন, সম্পদ ও নিট মূল্য, রিপোর্ট, CSV ইমপোর্ট/এক্সপোর্ট, ব্যাকআপ-রিস্টোর। বাংলা/English, লাইট/ডার্ক মোড, মোবাইল-বান্ধব।

**Stack:** Next.js 15 (App Router) · React 19 · Tailwind CSS 4 · Supabase (Postgres + Auth + Storage, Row Level Security) · Vercel

---

## ১. সেটআপ (একবার, ~১৫ মিনিট)

### ক) Supabase
1. [supabase.com](https://supabase.com) → **New project** (Region: Singapore — বাংলাদেশের সবচেয়ে কাছে)।
2. **SQL Editor** → `supabase/migrations/0001_init.sql` পুরোটা পেস্ট করে **Run**।
3. একইভাবে `supabase/migrations/0002_storage.sql` রান করুন (রসিদ আপলোডের প্রাইভেট বাকেট)।
4. **Project Settings → API** থেকে `Project URL` ও `anon public` key কপি করুন।
5. **Authentication → URL Configuration**
   - Site URL: `https://<আপনার-vercel-ডোমেইন>`
   - Redirect URLs: `https://<আপনার-vercel-ডোমেইন>/auth/callback` (লোকাল টেস্টের জন্য `http://localhost:3000/auth/callback`)

### খ) লোকালি চালানো (ঐচ্ছিক)
```bash
cp .env.example .env.local      # URL ও anon key বসান
npm install
npm run dev                      # http://localhost:3000
```

### গ) GitHub → Vercel
```bash
git remote add origin https://github.com/<you>/taka-khata.git
git push -u origin main
```
Vercel → **Add New Project** → রিপো ইমপোর্ট → **Environment Variables**:

| Name | Value |
|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | Supabase Project URL |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | anon public key |
| `ALLOWED_EMAILS` | `you@example.com` (শুধু আপনি; পাবলিক লঞ্চে ফাঁকা রাখুন) |

**Deploy** চাপুন। প্রথমবার অ্যাপে **নতুন অ্যাকাউন্ট** খুলে ইমেইল নিশ্চিত করুন।

### ঘ) শুধু নিজের জন্য রাখতে চাইলে
নিজের অ্যাকাউন্ট খোলার পর Supabase → **Authentication → Sign In / Providers → Allow new users to sign up** বন্ধ করুন। `ALLOWED_EMAILS` অ্যাপ লেভেলে বাড়তি সুরক্ষা দেয়।

### পাবলিক লঞ্চের সময়
ডিজাইন শুরু থেকেই multi-user: প্রতিটি সারিতে `user_id`, আর RLS নিশ্চিত করে কেউ অন্যের ডেটা দেখতে/লিখতে পারবে না (টেস্টেড)। লঞ্চে শুধু `ALLOWED_EMAILS` ফাঁকা করুন ও sign-up চালু করুন। Supabase-এ custom SMTP (যেমন Resend) সেট করুন — ডিফল্ট ইমেইল লিমিট খুব কম।

## ২. হিসাবের নিয়ম (Financial accuracy)

ব্যালেন্স কখনো আলাদাভাবে সংরক্ষণ হয় না; প্রতিটি সংখ্যা `opening_balance + লেনদেন` থেকে হিসাব হয় (`src/lib/finance/engine.ts`)। তাই কোনো লেনদেন এডিট/ডিলিট করলে সব ব্যালেন্স ও রিপোর্ট নিজে থেকেই ঠিক হয়ে যায়। টাকা অ্যাপের ভেতরে পয়সা (integer) হিসেবে, ডেটাবেসে `numeric(14,2)` — floating-point ভুল নেই।

| লেনদেন | অ্যাকাউন্টে প্রভাব | আয়/খরচে প্রভাব |
|---|---|---|
| আয় | +পরিমাণ − ফি | আয় (ফি = খরচ) |
| খরচ | −পরিমাণ | খরচ |
| ট্রান্সফার | উৎস −(পরিমাণ+ফি), গন্তব্য +পরিমাণ | শুধু ফি খরচ |
| ধার নেওয়া | +পরিমাণ | কিছুই না (দায় বাড়ে) |
| ধার দেওয়া | −পরিমাণ | কিছুই না (পাওনা বাড়ে) |
| দেনা পরিশোধ | −(আসল+সুদ+ফি) | সুদ ও ফি খরচ; আসল নয় |
| পাওনা আদায় | +(আসল+সুদ) − ফি | সুদ আয়; আসল নয় |
| রিফান্ড | +পরিমাণ | সেই ক্যাটাগরির খরচ কমে |
| ব্যালেন্স সংশোধন | ±পার্থক্য | কিছুই না |
| শুরুর ব্যালেন্স | ব্যালেন্সে যোগ | আয় নয় |

- নিট মূল্য = মোট সম্পদ − মোট দায়। সঞ্চয় লক্ষ্য শুধু অ্যাকাউন্টের টাকার "চিহ্নিত অংশ" — সম্পদে দ্বিতীয়বার যোগ হয় না।
- বিল কখনো আপনা-আপনি "পরিশোধিত" হয় না; শুধু পরিশোধের লেনদেন লিখলে (একই বিল দুবার পরিশোধ ডেটাবেসেই আটকানো)।
- বার্ষিক সরল সুদ প্রতিদিনের বাকি আসলের ওপর হিসাব হয়; পরিশোধে আগে সুদ, পরে আসল ভাগ করার সাজেশন দেয় (আপনি বদলাতে পারেন)।
- ডুপ্লিকেট: একই দিন/অ্যাকাউন্ট/পরিমাণের লেনদেনে সতর্কবার্তা; ইমপোর্টে ফিঙ্গারপ্রিন্ট দিয়ে বাদ।

## ৩. নিরাপত্তা
- Supabase Auth (ইমেইল + পাসওয়ার্ড, ইমেইল ভেরিফিকেশন, পাসওয়ার্ড রিসেট); middleware প্রতি রিকোয়েস্টে সেশন যাচাই করে।
- প্রতিটি টেবিলে RLS: `user_id = auth.uid()`। ট্রিগার নিশ্চিত করে কেউ অন্যের অ্যাকাউন্ট/ক্যাটাগরি রেফারেন্স করতে পারবে না।
- ডেটাবেস-লেভেলে ভ্যালিডেশন (পরিমাণ, ধরন, ক্যাটাগরি-টাইপ, লোনের দিক, তারিখ)।
- রসিদ প্রাইভেট বাকেটে, শুধু মালিকের ফোল্ডারে; ৫ মিনিটের signed URL দিয়ে খোলে।
- ব্যাংক পিন, পাসওয়ার্ড, ওটিপি বা পূর্ণ অ্যাকাউন্ট নম্বরের কোনো ঘর নেই (শুধু শেষ ৪ অঙ্ক)।
- ব্যাকআপ: সেটিংস → পূর্ণ JSON ব্যাকআপ; রিস্টোর একটি ট্রানজ্যাকশনে হয় (হয় সব, না হয় কিছুই না)। Supabase নিজেও দৈনিক ব্যাকআপ রাখে (প্ল্যান অনুযায়ী)।

## ৪. টেস্ট
```bash
npm test                         # ৪২টি ইউনিট টেস্ট: প্রতিটি হিসাবের নিয়ম, লোন/সুদ, বিল, বাজেট, ইমপোর্ট, অনুবাদ
```
ডেটাবেস টেস্ট (RLS, কনস্ট্রেইন্ট, রিস্টোর) — লোকাল Postgres লাগবে:
```bash
psql -f supabase/test/supabase_stub.sql -f supabase/migrations/0001_init.sql -f supabase/test/db_test.sql
```
এন্ড-টু-এন্ড ব্রাউজার টেস্ট (`e2e/flows.py`): আসল UI দিয়ে সাইন-আপ থেকে ব্যাকআপ-রিস্টোর পর্যন্ত ৪৩টি চেক, প্রতিটি সংখ্যা মিলিয়ে দেখে। `e2e/local-stack.mjs` একটি টেস্ট-ওনলি Supabase stand-in (আসল Postgres + RLS)।

## ৫. সীমাবদ্ধতা / পরের ধাপের আইডিয়া
- রিমাইন্ডার অ্যাপের ভেতরে ও ব্রাউজার নোটিফিকেশনে দেখায় (অ্যাপ খুললে)। অ্যাপ বন্ধ থাকলেও ইমেইল/পুশ চাইলে Supabase Edge Function + cron যোগ করতে হবে।
